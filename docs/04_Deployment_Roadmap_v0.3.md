## 3. 기술 진단·검증 (PRD 단계 1~2) — 디자인 완성과 병행

### 3.1 기존 시스템 진단
- 기존 페이지 소스·DB·호스팅·도메인 계약 현황
- 16개 Vimeo 영상 링크(ID·비공개 해시) 목록 추출
- 재사용/폐기 코드 구분

### 3.2 Vimeo Starter 확인
공식 도움말 기준으로 Starter(유료)는 도메인 단위 임베드 제한, 컨트롤·재생바 숨김, 속도 버튼 끄기를 지원한다. 일부 외부 자료와 표기가 달라 계정에서 직접 확인한다.
- [ ] 영상 공개 범위에 '특정 도메인' 임베드 옵션 표시 여부
- [ ] 모양(Appearance) 탭에서 재생바·속도 끄기, 임베드 프리셋으로 16개 일괄 적용
- [ ] 'Vimeo에서 숨김' 설정 (현재 링크에 비공개 해시가 없어 공개 영상일 가능성)
- [ ] 개발자 앱·API 토큰 발급 (영상 길이·썸네일 자동 조회용. 불가 시 길이 수동 입력)
- 용량: 저장 2TB, 월 트래픽 2TB → 100명 미만·16개 영상 규모에 충분

PoC 항목 (요금제와 무관, LMS 코드에서 구현)
- 시청한 고유 구간 누적 기반 진도 계산
- 최초 학습 시 앞으로 건너뛰기 차단, 재생속도 고정
- 이어보기, 이수 후 자유 재생
- 탭 전환·네트워크 끊김·브라우저 종료 시 진도 유실 범위
- PC Chrome·Edge, 태블릿 Samsung Internet(필요 시 iPad Safari)에서 동작
- 실행 위치: Vercel 시험 주소 (Vimeo 허용 도메인에 추가)

### 3.3 Supabase·Vercel PoC
- **사번 로그인**: Supabase Auth는 이메일·전화번호 기반이다. 연락처를 수집하지 않으므로 아래 중 선택
  - (a) 사번을 내부용 가상 이메일로 변환(예: `사번@staff.internal`)해 Supabase Auth 사용, 비밀번호 초기화는 관리자 API로 처리
  - (b) 자체 인증(사번+비밀번호 해시) + 세션 관리
  - → 권장 (a): 잠금·세션·해시를 Supabase가 처리. 관리자 초기화·첫 로그인 비밀번호 변경 흐름 PoC 필요
- **권한(RLS)**: 직원=본인 데이터, 부서담당자=소속 부서, 중앙관리자=전체를 DB 행 수준 보안 정책으로 강제. 엑셀 출력도 같은 정책 적용 확인
- **진도 저장 부하**: 재생 중 수 초 간격 저장 → Vercel 함수 호출량·Supabase 쓰기량 측정
- PDF 이수증: 한글 폰트 임베드, 직인 이미지, 출력 품질 (Vercel 함수 실행시간 내 생성 확인)
- CSV 일괄등록 → 엑셀 출력 왕복 (한글 인코딩, 날짜 형식)

### 3.4 PoC 결과 반영
- 불가능하거나 비용이 큰 항목은 PRD 요구사항 조정 후 v0.2 확정

## 4. 아키텍처·인프라 설계

### 4.1 기술 스택 결정 (2026-10-08)

| 계층 | 선택 | 역할 |
|---|---|---|
| 웹앱·서버 함수 | **Vercel (Pro)** | 화면, API, 진도·평가·이수 판정, PDF·엑셀 생성 |
| DB·인증·파일 | **Supabase (Pro)** | Postgres, Auth, RLS, Storage(썸네일·첨부·직인·이수증) |
| 영상 | **Vimeo Starter** | 비공개 영상 저장·스트리밍, 도메인 제한 임베드 |
| 도메인 | 병원 하위 도메인 | Vercel 연결 + Vimeo 허용 도메인 등록 |
| 소스 저장소 | GitHub `purmemt-star/purme-edu` | 문서·코드, Vercel Git 연동 자동 배포 |

검토 후 제외: **GAS(Google Apps Script)** — 웹앱이 googleusercontent.com 하위에서 실행되어 Vimeo 도메인 제한과 충돌, 시트 DB의 진도 저장 동시성·할당량 한계, 감사로그·백업 수준 부족.

### 4.2 요금제·리전 원칙
- Vercel: Hobby는 비상업용 → **Pro** 필요. 서버 함수 리전 **서울**
- Supabase: Free는 미사용 시 일시정지·백업 제한 → **Pro** 필요. 프로젝트 리전 **서울(ap-northeast-2)**
- 정확한 월 비용은 예산 산정 시 각 사 요금표로 확인

### 4.3 기술 설계 문서
- 시스템 구성도, ADR(본 결정 기록 포함)
- 데이터 모델 상세(PRD §10 11개 엔터티) → Supabase 스키마·RLS 정책
- API 명세 (Vercel 함수)
- 역할 기반 권한 매트릭스 (직원 / 부서담당자-소속부서 한정 / 중앙관리자)
- 서버 측 진도·평가·이수 판정 로직 명세, 중복 방지 규칙 (DB 유니크 제약)
- 관리자 전용 키(Supabase service role)는 Vercel 서버 함수에서만 사용, 브라우저·저장소 노출 금지

### 4.4 사전 협의 (병원 정보보호·전산)
- 외부 클라우드(Vercel·Supabase, 해외 법인) 사용 허용 여부
- 개인정보 처리 위탁 고지·계약(DPA) 필요 여부
- 접속기록 보관 기준, 관리자 2단계 인증 적용

### 4.5 인프라 구성 항목
- 환경 분리: 개발 / 스테이징(검수) / 운영 — Vercel 미리보기 배포 + Supabase 프로젝트 2개(스테이징·운영)
- 도메인, DNS, HTTPS 인증서 (Vercel 자동 갱신)
- DB 자동 백업, 보관 주기, **복구 리허설** (필요 시 시점 복구 옵션 검토)
- 모니터링·장애 알림, 애플리케이션·접속 로그
- 배포 파이프라인(Git 연동 자동 배포)과 롤백 방법(이전 배포로 즉시 전환, DB 마이그레이션 롤백 절차)
